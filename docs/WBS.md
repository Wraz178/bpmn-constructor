# Иерархическая структура работ (ИСР) проекта «Визуально-графический конструктор BPMN»

ИСР построена по модели жизненного цикла проекта информационной системы
(ГОСТ Р 57193-2016 / ISO/IEC/IEEE 15288, каскадная модель с итерациями):
инициация → анализ требований → проектирование → разработка → тестирование →
внедрение и сопровождение. Каждому этапу соответствует пакет работ, каталог
репозитория и ветка Git.

## 2. Стратегия ветвления

```
main ──────────────────────────────────────────────● v1.0.0
  └── develop ──┬──────┬──────┬──────┬──────┬──────┘
                │      │      │      │      │
                │      │      │      │      └── feature/deployment
                │      │      │      └───────── feature/testing
                │      │      └──────────────── feature/development
                │      └─────────────────────── feature/design
                └────────────────────────────── feature/analysis
```

- `main` — защищённая ветка со стабильными версиями; изменения попадают
  только через pull request из `develop` после ревью.
- `develop` — интеграционная ветка; в неё сливаются ветки этапов.
- `feature/<этап>` — рабочие ветки пакетов работ ИСР (п. 2–6).
- Коммиты оформляются по соглашению Conventional Commits
  (`docs:`, `feat:`, `test:`, `chore:`).

## 3. Категории пользователей репозитория и права доступа

| Категория пользователей | Роль в проекте | Право доступа GitHub | Ветки, в которые разрешена запись |
|---|---|---|---|
| Руководитель проекта (владелец репозитория) | Управление проектом, приёмка результатов, релизы | Admin | все, включая `main` |
| Аналитик | Требования, ТЗ, глоссарий | Write | `feature/analysis`, `develop` (через PR) |
| Архитектор / проектировщик | Архитектура, модель данных, UI | Write | `feature/design`, `develop` (через PR) |
| Разработчик | Исходный код приложения | Write | `feature/development`, `develop` (через PR) |
| Тестировщик | Тест-кейсы, автотесты, отчёты о дефектах | Write (Triage для внешних) | `feature/testing`, Issues |
| Инженер внедрения (DevOps) | Инструкции развёртывания, релизы | Maintain | `feature/deployment`, `main` (через PR) |
| Преподаватель / рецензент | Проверка работы | Read | — (чтение, комментарии в Issues) |
| Заказчик, пользователи | Ознакомление с проектом | Read (публичный репозиторий) | — |

Правила для `main`: запрет прямых push, обязательный pull request с одним
одобрением, обязательное прохождение проверок. Ответственные за каталоги
закреплены в файле `.github/CODEOWNERS`.

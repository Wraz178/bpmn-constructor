# Техническое задание на программный продукт «Визуально-графический конструктор BPMN»

Документ составлен в соответствии со структурой ГОСТ 19.201-78
«ЕСПД. Техническое задание. Требования к содержанию и оформлению».

## 1. Введение

**Наименование программы:** «BPMN Constructor» — визуально-графический
конструктор диаграмм бизнес-процессов в нотации BPMN 2.0.

**Краткая характеристика области применения.** Программа предназначена для
аналитиков, проектировщиков информационных систем, преподавателей и студентов,
которым требуется быстро построить, проверить и сохранить диаграмму
бизнес-процесса. Область применения — анализ и проектирование ИС,
документирование процессов организации, учебный процесс по дисциплинам,
связанным с моделированием бизнес-процессов.

**Объект, в котором предполагается использование.** Рабочее место аналитика
(персональный компьютер с современным веб-браузером); серверная часть не
требуется.

## 2. Основания для разработки

- Методические указания по выполнению рейтинговой работы по дисциплине
  «Проектная деятельность в ИТ» (МУИВ, кафедра информационных систем, 2024),
  вариант «с Ч до Щ» — «Разработка визуально-графического конструктора BPMN».
- Устав проекта (`docs/01_initiation/charter.md`).
- Спецификация OMG Business Process Model and Notation (BPMN) версии 2.0.2.

Наименование темы разработки: «Визуально-графический конструктор BPMN».
Условное обозначение: BPMN-C.

## 3. Назначение разработки

**Функциональное назначение:** создание, редактирование, проверка и экспорт
диаграмм бизнес-процессов в нотации BPMN 2.0 через графический интерфейс в
браузере.

**Эксплуатационное назначение:** применение на этапах анализа и
проектирования ИС для формализации процессов предметной области; подготовка
диаграмм для последующего импорта в промышленные BPM-системы (Camunda и
совместимые), поддерживающие BPMN 2.0 XML.

## 4. Требования к программе

### 4.1. Требования к функциональным характеристикам

| № | Требование | Приоритет |
|---|---|---|
| Ф1 | Палитра элементов: начальное, конечное, промежуточное события; задача; пользовательская задача; исключающий и параллельный шлюзы | Обязательно |
| Ф2 | Размещение элементов на холсте перетаскиванием (drag-and-drop) с привязкой к сетке | Обязательно |
| Ф3 | Перемещение элементов мышью с автоматическим перестроением потоков | Обязательно |
| Ф4 | Соединение элементов потоками управления в специальном режиме «Соединить» с проверкой допустимости (запрет потока из конечного события и в начальное, запрет дублей и петель) | Обязательно |
| Ф5 | Редактирование названия и документации элемента в панели свойств и по двойному щелчку | Обязательно |
| Ф6 | Удаление элементов и потоков (кнопка, клавиша Delete) с каскадным удалением связанных потоков | Обязательно |
| Ф7 | Проверка модели: наличие начального и конечного событий, элементы без входящих/исходящих потоков, шлюзы с недостаточным числом потоков | Обязательно |
| Ф8 | Сохранение и загрузка диаграммы в хранилище браузера (localStorage) | Обязательно |
| Ф9 | Экспорт диаграммы в BPMN 2.0 XML (семантика процесса и графическая информация BPMNDI) | Обязательно |
| Ф10 | Экспорт и импорт диаграммы в формате JSON | Желательно |
| Ф11 | Отображение статистики (число элементов и потоков) и строки состояния | Желательно |

### 4.2. Требования к надёжности

- Некорректный файл импорта не должен приводить к потере текущей диаграммы:
  выводится сообщение об ошибке, модель остаётся без изменений.
- Все операции над моделью выполняются через единый API модуля `model.js`,
  обеспечивающий целостность ссылок между элементами и потоками.

### 4.3. Условия эксплуатации

Программа работает в браузерах Chrome 100+, Firefox 100+, Safari 15+ на
операционных системах Windows, macOS, Linux. Специальной подготовки
пользователя не требуется; достаточно знания нотации BPMN на базовом уровне.

### 4.4. Требования к составу и параметрам технических средств

Персональный компьютер с разрешением экрана не менее 1280×720, мышь или
трекпад; доступ в Интернет не требуется.

### 4.5. Требования к информационной и программной совместимости

- Формат экспорта — BPMN 2.0 XML (пространства имён OMG `MODEL`, `DI`, `DC`,
  `DD`), пригодный для открытия в bpmn.io / Camunda Modeler.
- Исходный код — HTML5, CSS3, JavaScript (ECMAScript 2020), без сторонних
  библиотек и инструментов сборки.

### 4.6. Требования к маркировке, упаковке, транспортированию и хранению

Программа распространяется в виде публичного репозитория Git (GitHub).
Версии маркируются тегами вида `vX.Y.Z` (семантическое версионирование).

## 6. Технико-экономические показатели

Ориентировочная трудоёмкость — 40 человеко-часов. Экономическая
эффективность достигается отсутствием затрат на лицензии и серверную
инфраструктуру: приложение запускается локально из файла.

## 8. Порядок контроля и приёмки

Приёмка выполняется по тест-кейсам `tests/test_cases.md`: проверка
функциональных требований Ф1–Ф11 вручную в браузере и автоматическая проверка
модели (`tests/index.html`). Критерий приёмки — успешное прохождение всех
обязательных тест-кейсов и корректное открытие экспортированного файла
`diagram.bpmn` во внешнем редакторе BPMN.

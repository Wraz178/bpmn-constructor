# Архитектура приложения «BPMN Constructor»

## 1. Общая схема

Приложение является одностраничным (SPA) и выполняется целиком в браузере.
Архитектура построена по принципу разделения модели и представления:

```
┌────────────────────────────────────────────────────────────┐
│  index.html / styles.css — разметка и оформление интерфейса│
├────────────────────────────────────────────────────────────┤
│  app.js — контроллер и представление                       │
│   • палитра (drag-and-drop)      • холст SVG (render)      │
│   • панель свойств               • панель инструментов     │
│   • обработка мыши и клавиатуры  • localStorage, файлы     │
├──────────────────────────┬─────────────────────────────────┤
│  model.js — модель       │  bpmn-export.js — экспорт       │
│   DiagramModel, NODE_TYPES│   toBpmnXml(), anchorPoint()   │
│   addNode/addFlow/remove │                                 │
│   validate(), toJSON()   │                                 │
└──────────────────────────┴─────────────────────────────────┘
```

- **model.js** не зависит от DOM и может исполняться в Node.js /
  JavaScriptCore, что позволяет тестировать бизнес-логику автономно.
- **bpmn-export.js** преобразует модель в BPMN 2.0 XML (семантическая часть
  `bpmn:process` и графическая часть `bpmndi:BPMNDiagram`).
- **app.js** реализует паттерн «однонаправленный поток данных»: любое действие
  пользователя изменяет модель, после чего вызывается `render()`, полностью
  перерисовывающий холст, панель свойств, статистику и результаты валидации.

## 2. Модель данных диаграммы

```json
{
  "version": 1,
  "processId": "Process_1",
  "processName": "Бизнес-процесс",
  "nodes": [
    { "id": "Task_…", "type": "task", "x": 300, "y": 200,
      "width": 120, "height": 70, "name": "Проверить заявку",
      "documentation": "" }
  ],
  "flows": [
    { "id": "Flow_…", "sourceRef": "StartEvent_…", "targetRef": "Task_…",
      "name": "" }
  ]
}
```

| Сущность | Атрибуты | Ограничения |
|---|---|---|
| Node (элемент) | id, type, x, y, width, height, name, documentation | type ∈ NODE_TYPES; координаты — центр элемента |
| Flow (поток) | id, sourceRef, targetRef, name | source ≠ target; source не endEvent; target не startEvent; пара (source, target) уникальна |

Внутри модели элементы и потоки хранятся в `Map` для доступа за O(1);
при удалении элемента каскадно удаляются связанные потоки.

## 3. Пользовательский интерфейс

| Область | Назначение |
|---|---|
| Панель инструментов | Режимы «Выбор» / «Соединить», удаление, сохранение, загрузка, экспорт, импорт, очистка |
| Палитра (слева) | Шаблоны элементов BPMN, перетаскиваемые на холст |
| Холст (центр) | SVG 2000×1400 с сеткой; слои `layer-flows` и `layer-nodes` |
| Панель свойств (справа) | Атрибуты выделенного элемента, статистика, результаты проверки |
| Строка состояния | Сообщения о выполненных действиях и ошибках |

Сценарии использования: 1) построение диаграммы перетаскиванием и
соединением элементов; 2) редактирование подписей; 3) проверка модели;
4) сохранение/загрузка; 5) экспорт в BPMN XML для внешних систем.

## 4. Алгоритм расчёта точек соединения

Поток изображается отрезком между точками на границах фигур. Для элемента с
центром (x, y) и размерами w×h точка выхода в направлении другого элемента
вычисляется масштабированием вектора между центрами до пересечения с
ограничивающим прямоугольником (`anchorPoint`). Для окружностей и ромбов
такое приближение даёт визуально корректный результат при малых размерах
фигур; стрелка потока рисуется SVG-маркером.

## 5. Решения по хранению

- Текущая диаграмма сохраняется в `localStorage` под ключом
  `bpmn-constructor.diagram` (JSON).
- Обмен с внешними системами — через файлы `diagram.json` и `diagram.bpmn`,
  формируемые на клиенте (Blob + ссылка для скачивания).
